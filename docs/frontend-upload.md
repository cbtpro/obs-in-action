## 上传进度

单文件上传使用 Axios 的 `onUploadProgress`。`total` 可能不存在，计算百分比前必须判空。

分片进度由三部分组成：

```text
云端已确认字节 + 本轮已完成字节 + 当前在途字节
──────────────────────────────────────────────
                  文件总大小
```

完成接口返回前，进度最多展示 99%，避免“已经 100% 但仍未完成”的误导。

初始化前会并行计算会话指纹和完整文件 SHA-256。SHA-256 命中已有文件时，服务端直接返回文件信息，前端将任务标记为完成，不再上传分片。

## 取消、暂停与重试

- 取消使用 `AbortController`，组件卸载时停止相关请求。
- Axios 的取消错误应静默处理，不展示成业务失败。
- 分片暂停只停止调度新分片，让在途分片完成，减少重复传输。
- 单片失败使用有限次数的指数退避；达到上限后，其他 worker 不再领取新任务。
- 每片在首次发送前计算一次 Base64 MD5；重试复用同一摘要。
- 文件任务失败后保留在列表中，重试复用原任务，避免重复条目。

## 图片预览

使用 `URL.createObjectURL(file)` 生成本地预览，并在不再使用时调用 `URL.revokeObjectURL`。

只回收由当前页面创建的 `blob:` URL，不要尝试回收服务端返回的远程 URL。

## HTTPS 开发环境

[`vite.config.ts`](../frontend/vite.config.ts) 使用本地证书启动 HTTPS，避免 HTTPS 页面加载 HTTP 对象地址产生 mixed content。证书生成命令和信任说明见[快速开始](./getting-started.md#4-准备本地-https-证书)。

⚠️ `frontend/.ssl/` 是本地目录，已被整体忽略。不要提交证书私钥；仓库只保留可审计的生成脚本。

## 并发边界

当前每个文件使用 3 个 worker。该数值是项目经验值，不是通用最优值。调整时需要同时观察：

- 用户网络和浏览器协议；
- 后端线程与数据库连接池；
- 存储厂商 QPS 和限流；
- 同时上传的文件任务数量。

HTTP/2 可以承载更多并行流，因此不能长期依赖浏览器连接数作为全局限流器。高并发场景应增加跨任务的统一信号量。
